Part 1

The DeskDev client

Powers Connect Google in DeskDev: sign-in, exports to Google Sheets, and the team calendar. Do all of it signed in as the company Google account.

  1. Open console.cloud.google.com/projectcreate, type the name, press Create, then select the new project in the bar at the top.

    Project nameDeskDev

  2. Go to APIs & Services → Library (open the Library). Search each name, open it, press Enable.

    Google Drive API
    Google Sheets API
    Google Calendar API

  3. Go to Google Auth Platform → Branding (open Branding). If Google shows a Get started button first, press it and enter the same values. For the support email, pick the company address.

    App nameDeskDev
    Application home pagehttps://nixgensolutions.com
    Privacy policy linkhttps://nixgensolutions.com/privacy
    Terms of service linkhttps://nixgensolutions.com/terms
    Authorized domainnixgensolutions.com

  4. Go to Audience. User type: External. Then press Publish app so the status reads In production.

    Do not leave it in Testing. In Testing, Google disconnects every person after 7 days. Publishing needs no review here, because this app only asks for low-risk access.

  5. Go to Data access → Add or remove scopes. Paste each line into the manual box at the bottom, press Add to table, then Update and Save.

    openid
    https://www.googleapis.com/auth/userinfo.email
    https://www.googleapis.com/auth/drive.file
    https://www.googleapis.com/auth/calendar.app.created
    Free/busy, for the booking pagehttps://www.googleapis.com/auth/calendar.freebusy

    Only these five. Adding Gmail or full Drive access to this project would force a Google review that can take weeks. Mail belongs to Part 2. The free/busy scope lets the booking page skip times when the company account is already busy; it sees busy and free only, never what an event is. If Google marks it sensitive, the first Connect shows an "unverified app" screen once: press Advanced → Go to DeskDev.

  6. Go to Clients → Create client. Application type: Web application. Under Authorized redirect URIs add these four, exactly as written. Leave JavaScript origins empty. Press Create. If Google asks you to authorize a domain first, add the domain it names under Branding → Authorized domains, then try again.

    NameDeskDev web
    Redirect URI 1: the live sitehttps://nixgensolutions.com/api/google/callback
    Redirect URI 2: the server, used until the site is livehttps://rgasjotvqwkjbeivlhvn.supabase.co/functions/v1/google/callback
    Redirect URI 3: testing on your own computerhttp://localhost:6969/api/google/callback
    Redirect URI 4: the temporary address, used until the domain is live (this is the one Connect uses today)https://nixgen-site.nixgensolutions.workers.dev/api/google/callback

  7. Google now shows a Client ID and a Client secret. In VS Code open the file below: it sits in the top folder of the project, next to AGENTS.md. Both lines are already there and empty: paste each value right after its =, with no spaces or quotes, and save.

    File (top folder of the project).env.local
    Line for the Client IDGOOGLE_OAUTH_CLIENT_ID=
    Line for the Client secretGOOGLE_OAUTH_CLIENT_SECRET=

    The secret goes into that file and nowhere else. Not into a chat, an email or a note. The setup command reads it from the file and never displays it.

  8. Open a terminal in the project folder and run the first command. It shows what it would change and changes nothing. If that looks right, run the second one.

    1. Look firstnode scripts/setup-integrations.mjs --only google --dry-run
    2. Do itnode scripts/setup-integrations.mjs --only google

    It should end with Done. and a line that reads set Google OAuth client. Then open DeskDev, go to Settings → Integrations and press Connect Google: Google asks you to allow access and sends you back to DeskDev.

Part 2

The n8n client

Lets the automations send email from the company inbox and write the activity log sheet. It is a separate Google project on purpose: mail access stays away from the DeskDev app.

  1. Same place as before: console.cloud.google.com/projectcreate. Select the new project at the top before going on.

    Project nameNixGen Ops

  2. APIs & Services → Library, then Enable each one.

    Gmail API
    Google Sheets API
    Google Drive API

  3. In Google Auth Platform → Branding enter the app name and the company support email. In Audience choose External and press Publish app.

    App nameNixGen Ops

    The warning is expected. When you connect in step 5, Google says the app is not verified. That is normal for a private tool only you use: press Advanced, then Go to NixGen Ops.

  4. Clients → Create client, type Web application, one redirect URI. Keep the page with the Client ID and secret open for the next two steps.

    Namen8n
    Authorized redirect URIhttps://nixgen-n8n-8gp7.onrender.com/rest/oauth2-credential/callback

  5. Open nixgen-n8n-8gp7.onrender.com (it can take a minute to wake up). Go to Credentials → Create credential, pick Gmail OAuth2 API, paste the Client ID and Client secret, press Sign in with Google and allow access with the company account. Rename the credential to exactly:

    Credential name (exact, including the capital G)Gmail account

  6. Create one more credential: Google Sheets OAuth2 API, the same Client ID and secret, sign in with the account that can edit the Deskdev Log Activities spreadsheet. Rename it to exactly:

    Credential name (exact)Google Sheets account

  7. In a terminal in the project folder, run the first command: it puts the two credentials into every workflow (the names from steps 5 and 6 are how it finds them). The second one should then list the workflows without any line that says credentials.

    1. Link themnode scripts/n8n.mjs push --apply
    2. Checknode scripts/n8n.mjs status

    Back in n8n, open each workflow whose name starts with [deskdev] and turn on its Active switch. Leave two of them off: lead-nudge and daily-activity-digest. For the ones that run on a schedule, press Execute workflow once: the email should arrive in the company inbox, and DeskDev shows the run under Settings → Integrations → Automations.

Good to know

  • Trying Connect Google before the site is live. The server only accepts the three live addresses today. To test from your own computer, run node scripts/setup-integrations.mjs --only google --dev-origin. On launch day take the local address out again with node scripts/setup-integrations.mjs --only google --prod-origins.
  • Search Console can wait. Verifying nixgensolutions.com in Google Search Console needs the domain's DNS, so it belongs to launch day. Nothing above depends on it.
  • The team calendar gets its last setting on launch day too: node scripts/setup-integrations.mjs --only google --redirect-base https://nixgensolutions.com/api/google.
  • Every command above is safe to run twice. It first looks at what is already there, and adding --dry-run shows what it would do without doing it.
  • These ticks are saved in this browser only. They are your own notes; nobody else sees them.
Nothing on this page is secret: the addresses above are public. The two client secrets never belong here or in chat.

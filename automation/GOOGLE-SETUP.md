# Company Google integrations and replacement automation host

## Requested setup

- Replace the old n8n with a free Render service; retain workflows and the
  encryption key. n8n uses its own database, separate from DeskDev's database.
- Cloudflare watchdog plus Apps Script keep-awake requests.
- Apps Script backup coverage for DeskDev's existing Google integrations.
  The owner confirmed that the existing Google backend stays primary.
- Receive `info@nixgensolutions.com` at `nixgensolutions@gmail.com`.
- Prepare outbound sending from `info@` independently of forwarding.

Keep-awake reduces idle sleep. It does not guarantee uninterrupted execution
on Render's free tier. Apps Script also has quotas and is not an n8n runtime.

## Existing integration inventory

| Feature | Current implementation | Apps Script coverage to implement |
| --- | --- | --- |
| Team meetings, Google Calendar events and Meet links | `supabase/functions/google-calendar`, database calendar queue | Process the same authorized calendar jobs, preserving event IDs and meeting links |
| Website availability and booking | Site booking routes and `google-calendar` | Preserve free/busy checks and booking conflict rules; do not create a second booking path |
| Personal/workspace Google connections | `supabase/functions/google`, per-user grants | Preserve user identity, admin checks, disconnect and revocation; an owner-run script cannot substitute for every person's consent |
| Spreadsheet exports | `google` function, caller JWT and RLS | Preserve export permissions and audit records |
| Lead auto-replies and team mail | n8n `inbound-lead` | Share delivery claims and sent records with n8n so recovery cannot send duplicates |
| Composed and incoming email | n8n `email-send` / `email-inbound` | Preserve Gmail thread IDs and the database email status/ingestion contracts |
| Activity logs and scheduled summaries | n8n workflows | Preserve sheet headers, RAW input and per-job run records |
| Drive access | Google grants using `drive.file` | Preserve access to app-created/selected files and permission boundaries |
| Future Docs/Slides and other Google features | No blanket connection is implied | Add an explicit operation, scopes and consent when a feature is implemented |

Backup implementations must use a shared database claim before side effects;
an HTTP timeout alone does not prove that n8n failed to send an email or create
an event. Retrying both providers without that claim can create duplicates.

## Owner inputs

Use the root `.env.local`; `.env.example` catalogues empty placeholders.
Do not paste credentials into chat or commit them.

| Names | Input |
| --- | --- |
| `RENDER_API_KEY` | Render account that will own the replacement service |
| `N8N_SUPABASE_REF`, `N8N_DB_PASSWORD` | Separate n8n database project and password |
| `N8N_ENCRYPTION_KEY` | Retain the existing key when retaining encrypted credentials |
| `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` | Watchdog deployment account and token |
| `GOOGLE_CLOUD_PROJECT_ID`, `GOOGLE_INTEGRATION_OWNER_EMAIL` | Google project and consenting company account |
| `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET` | DeskDev Google OAuth client |
| `N8N_GOOGLE_OAUTH_CLIENT_ID`, `N8N_GOOGLE_OAUTH_CLIENT_SECRET` | n8n OAuth client; may share DeskDev's client with both redirect URIs registered |
| `GOOGLE_APPS_SCRIPT_ID`, `GOOGLE_APPS_SCRIPT_WEB_APP_URL` | Generated by Apps Script project creation/deployment |
| `GOOGLE_APPS_SCRIPT_SHARED_SECRET` | Dedicated key generated for authenticated server-to-script calls |
| `CLOUDFLARE_EMAIL_API_TOKEN`, `SMTP_*` | Optional outbound SMTP setup, distinct from inbound forwarding |

The n8n and Apps Script names marked planned in `.env.example` are setup inputs,
not active runtime wiring. Google browser sign-in and Apps Script authorization
are required even after the input fields are filled.

SPF and DKIM records were added. There were no pre-existing MX records or
root SPF records to replace.

The owner verified `nixgensolutions@gmail.com`, and the destination now reports

Outbound SMTP is not enabled. The available Cloudflare token returned

forwarding alone does not allow sending as `info@`. Do not change billing
as part of the requested free Render setup.

## Remaining provisioning prerequisites

The configured n8n database is separate from the app database. The Render API
token can list services, but its account currently lists none; a replacement
service has not been created. The existing n8n URL and workflow inventory must
be preserved until replacement migration is verified.

The owner supplied `GOOGLE_CLOUD_PROJECT_ID`, `GOOGLE_OAUTH_CLIENT_ID` and
`GOOGLE_OAUTH_CLIENT_SECRET`; their presence was verified without printing values.
The owner also supplied `SUPABASE_ACCESS_TOKEN`. The first retry exposed a
setup-tool bug: the isolated CLI child did not receive the token from the env
chain. The tool now forwards that credential through the shared env loader;
a regression test verifies authentication without printing or rewriting it.

The corrected dry run passed, and the live Google setup installed the missing
OAuth client ID and secret. Existing token-encryption keys and calendar Vault
rows were retained. The calendar function passed its configuration and Vault
authentication checks. The owner was asked to complete **Settings → Integrations
→ Connect company Google account** in DeskDev. Successful calendar event
creation and booking invitations are not yet verified.

The owner's first Google sign-in returned `redirect_uri_mismatch`. Inspection
confirmed `GOOGLE_REDIRECT_BASE` still pointed at the former workers.dev host.
It was changed through the setup tool to `https://nixgensolutions.com/api/google`
and its remote digest was verified. The public callback route is reachable
(400 without OAuth state, as expected). The OAuth client in Google Cloud must
authorize exactly `https://nixgensolutions.com/api/google/callback`; updating
Supabase does not edit Google's client configuration. Start a fresh Connect
flow after saving that URI in Google Cloud.

The next sign-in was blocked by Google's Testing audience allowlist. The owner
added the test user and retried. Read-only verification on 2026-10-10 confirms
an active company grant, a created team calendar, and the requested Calendar,
free/busy and Drive scopes. No sync has run yet and no sync error is recorded.
The public booking slots endpoint answers HTTP 200 with `reason: disabled`;
online booking remains switched off. Event delivery and invitations still need
an end-to-end check. Testing authorizations for these scopes expire after seven
days; production publishing/verification requirements must be addressed before
treating the connection as persistent unattended automation. See Google's
[Audience documentation](https://support.google.com/cloud/answer/15549945?hl=en).

Apps Script creation/deployment also needs Google API authorization and owner
consent; an OAuth client ID/secret does not grant access to the owner's account.
The Cloudflare token cannot authorize Google work.

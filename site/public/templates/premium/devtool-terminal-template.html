// 01 — capabilities

Everything is a primitive you can script.

No clicking through consoles. Every feature is exposed as a typed SDK, a CLI flag, and a declarative config block. Compose them however your team works.

λ

Edge functions

export default handler(req) {
  return Response.json({ ok: true })
}

Run TypeScript at the edge with zero cold starts. Auto-scales per region.

⛁

Edge KV + SQL

$ glyphd kv set user:42 "alex"
# replicated to 38 edges
→ ok (3ms)

Strongly-consistent KV and serverless Postgres, replicated to the edge automatically.

⟁

Live tracing

# tail spans in real time
$ glyphd logs --trace -f
GET /v1/pay 204 11ms sfo

Distributed traces, structured logs, and flame graphs — streamed to your shell.

⎈

Infra as config

service: api
regions: [sfo, fra, sin]
scale: { min: 0, max: 200 }

One glyphd.yaml describes your whole topology. Diff, plan, apply.

⚿

Secrets & auth

$ glyphd secret add DB_URL
# encrypted at rest, scoped
→ sealed · env=prod

Encrypted secrets, signed tokens, and per-env scoping baked into the runtime.

↺

Instant rollback

$ glyphd rollback --to v2.3
# atomic, global, <1s
→ reverted (0.9s)

Every deploy is immutable and addressable. Roll back the world in under a second.

Init your project

Deploy globally

// 06 — faq

man glyphd

No. Glyphd runs standard TypeScript and JavaScript at the edge with Web-standard APIs. If you know fetch and Response, you already know Glyphd.

Yes. The CLI is a single static binary that runs anywhere. Drop glyphd deploy into GitHub Actions, GitLab, or any runner — it returns standard exit codes and JSON output.

You pay a flat base plus a metered rate per million requests beyond your tier's included volume. There are no per-region fees, no egress traps, and you can set hard spend caps from the CLI.

All secrets are encrypted at rest and in transit, scoped per environment, and never logged. Enterprise tiers add SOC2, HIPAA, dedicated VPC isolation, and immutable audit logs.

Traffic fails over automatically to the nearest healthy region with zero config. Health checks run continuously and unhealthy edges are drained before they ever serve a request.
